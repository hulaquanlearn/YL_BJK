# OpenClaw 网页正式部署任务

## 本次更新范围

- 保留现有深红侧栏、浅灰背景和白色卡片架构，优化卡片、表格、边框、阴影和状态色。
- 库存列表隐藏“盘点状态”，新增接口已有的 `spec`“规格型号”字段。
- 盘点状态继续在备件详情中展示。
- 左侧栏支持展开/收起，并在当前浏览器中记住选择。
- 出入库弹窗新增必填原因，适配服务端库存流水规则。
- 本次只有网页文件更新，无数据库迁移、无后端 API 更新、无 Nginx 规则变更。

## 部署要求

1. 先执行 `pm2 describe spare-parts-web` 确认当前网页运行目录，不得猜测目录或影响 `spare-parts-api`、OpenClaw、Dify及其他PM2服务。
2. 备份当前网页运行目录、PM2清单和Nginx配置，在独立临时目录解压本包；不要直接覆盖正在运行的目录。
3. 在解压后的 `spare-parts-web-release` 目录必须执行：

   ```bash
   npm ci
   npm run build
   test -f dist/index.html
   npm prune --omit=dev
   ```

   任一步失败立即停止并回滚，禁止复用旧版 `dist`。
4. 检查包内不存在 `.env`、密码、API Key、Service Token或登录令牌。若现网目录存在自有环境配置，备份并原样保留，不得回传内容。
5. 构建成功后再切换网页目录，并执行：

   ```bash
   pm2 restart spare-parts-web --update-env || pm2 start ecosystem.config.cjs
   pm2 save
   ```

6. 网页仍只监听 `127.0.0.1:8503`，API仍只连接 `127.0.0.1:3000`；安全组不得开放8503或3000。
7. Nginx继续将网页域名代理到8503，将 `/api/` 代理到3000；不要改动现有HTTPS证书和其他站点配置。

## 上线验证

1. `pm2 status` 中 `spare-parts-web` 和 `spare-parts-api` 均为 `online`，且没有持续重启。
2. `curl -I http://127.0.0.1:8503/` 返回200；正式HTTPS首页和 `/api/health` 正常。
3. 匿名访问跳转登录；错误密码不能登录；普通用户不能看到出入库、审批和账号管理；管理员可以进入账号管理。
4. 库存列表能看到“规格型号”，不能看到“盘点状态”；打开详情能看到“规格型号”和“盘点状态”。
5. 左侧栏可以收起到图标模式，再次展开正常；刷新网页后保留上次状态。
6. 打开出入库弹窗能看到必填“出入库原因”，只检查界面，不提交正式出入库。
7. 检查浏览器控制台、Nginx和PM2日志，确认无500、API密钥、密码或登录令牌泄露。
8. 回报：备份路径、构建结果、PM2状态、监听地址、HTTPS/API健康状态、以上界面验证结果。所有敏感信息必须打码。
