# 全项目复查与经验总结（2026-09-30）

适用：网页端、小程序、Node/Express API。版本 V1.9.9 本地源码。本次未打包、未部署、未操作真实业务库。

## 经验教训

1. 先理解业务，再优化界面。3D 库位需要车间、货区、货架和视角操作，不能套用库存流水的原因、操作类型等筛选。每个字段必须对应真实数据或行为。
2. 入口、数据范围、操作权限是三个独立问题。功能入口可展示给所有登录角色；入口可见不代表可以读取所有人员材料，更不代表可以跨车间修改。客户端提示与服务端鉴权必须同时保留。
3. 网页、小程序和 API 必须使用同一业务边界。只修网页会留下小程序隐藏入口、旧接口或前端拦截差异。最终权限来自服务器查询的当前账号，而不是客户端保存的角色。
4. 日期控件属于它所控制的内容。记录日期放在记录表旁；月度考评选月份并点击周卡片；任务不需要额外周筛选。移除重复日期、重复汇总、相同动作的两套按钮。
5. 统一的是组件和规则，不是所有页面的配色与结构。备件保留红色、工程保留青绿色、工作保留蓝紫色；尺寸、字号、按钮对齐和弹窗行为一致。手机单独验收，不能靠电脑截图推断。
6. 不用常驻长说明替代合理交互。统计与 AI 规则集中说明；操作风险放在对应提交界面；未发布状态与满分分开显示；账号展示岗位，不夹带权限括号。
7. AI 建议必须来自已提交材料与维护的评分标准，负责人复核后发布。材料不足、模型不可用和未发布都必须明确表示，不把建议、空值或待复核当成正式分数。
8. 实物照片、类别参考图片、单个 3D 模型和库位模型用途不同，不能互相冒充。备件与专用模型的新增数据库匹配字段仍按既定后续计划处理，本次未擅自迁移。
9. 本地预览、单元/接口测试、微信开发者工具、真机、生产验收是不同证据。部署需同步网页/API；小程序修改还需独立上传与发布，旧 V1.9.8 包不能包含本次源码改动。

## 本次直接修复

- 工作管理中心及两个工作子模块入口不再按岗位隐藏。未授权角色进入时展示功能说明和访问提示，不挂载业务组件、不请求受限业务数据；原有 API 数据权限保持不变。
- 网页的维护控件对各登录角色可发现；写控件绑定具体操作权限，阻止没有权限的点击、键盘触发和拖入文件。车间管理员浏览其他车间时不能打开对应的写入控件。批量选择仍只纳入可编辑记录。
- 新建盘点入口展示给所有登录角色，提交资格仍由所属车间、前端处理函数与 API 校验决定。
- 小程序首页新增备件、盘点单入口、账号管理入口以及详情出入库/停用和审批操作可见；原有 requireWrite、所属车间检查、请求拦截和服务端授权继续阻止越权。库存统计仍在库存概况中可进入。
- 小程序账号身份文字去掉“备件只读”等后缀，保持与网页一致。权限不足在具体操作时反馈。
- 修改密码接口新增按账号 15 分钟 8 次限流，不因更换 IP 或同账号不同会话令牌而重置；另一个账号不受该账号限额影响。保持原有密码策略兼容，不改用户密码、不撤销现有会话。
- 考评初始加载阶段不再误显示“未配置人员”，数据加载失败给出重试入口。

## 权限矩阵

所有登录角色均能发现网页各中心及功能导航；未登录仍须登录。小程序展示其已实现的功能，不虚构尚未实现的网页模块。

| 功能 | 系统管理员 | 车间管理员 | 班长/组长/普通车间人员 |
| --- | --- | --- | --- |
| 库存、流水、补货、统计、3D、设备/模型查询 | 查询全部 | 查询全部 | 查询现有共享读取范围 |
| 备件、出入库、设备关系、库位维护 | 全部车间 | 仅所属车间 | 不得修改 |
| 被多个车间共用的物料图片等资源 | 可修改 | 不得覆盖跨车间共享资源 | 不得修改 |
| 类别模型、程序项目导入/删除 | 可维护 | 入口可见，不能执行系统维护 | 入口可见，不能执行系统维护 |
| 盘点单 | 可筛选全部；提交/审批 | 仅所属车间提交/审批 | 已分配车间可提交本车间；不能审批，未分配不可提交 |
| 工程知识 | 全部范围维护 | 按服务端所属车间授权维护 | 阅读/查询，不得修改 |
| 制曲工作记录/考评 | 管理与查看 | 制曲管理；其他车间只读查看 | 制曲组长仅本人；班长仅分配的组长；其他人员入口可见但不得读取材料 |
| 原粮检查通报 | 查看、整理、导出 | 原粮可维护；其他车间管理员只读 | 原粮人员只读；其他人员不得读取通报 |
| 账号管理 | 全部账号与岗位 | 仅本车间班长/组长，不得提升为管理员或调往其他车间 | 入口可见；不得枚举账号或维护他人身份 |
| 密码/退出 | 本人 | 本人 | 本人 |

系统维护中的“仅管理员”是明确的业务授权，不因入口可见而放开。具体行的状态条件也保留，例如已审批单不能再次审批、冻结库存不能出入库、停用型号不能新增关联。

## 安全检查结果

检查了鉴权链、角色与车间范围、个人/班组证据范围、账户权限提升、共享物料与批量事务、密码与会话失效、资源读取、上传/文档解析、HTML 清理、参数化查询、限流及 AI 出站控制。

- API 从数据库重新读取当前角色与启用状态；停用会话和无会话业务请求被拒绝。资产 Cookie 只适用于只读图片/模型，不能用于业务写入。
- 服务端在写入前及相关事务内检查车间归属；批量混合车间请求整批拒绝/回滚，不先写入部分项目。
- 班长只能访问自己负责组长的记录、照片和导出，未分配或跨车间普通人员不能读取考评/通报。
- 网页运行服务保护错误复制进 dist 的私密目录/文件，配置 CSP 等响应头；业务 API 和资产使用私有缓存策略及访问限流。
- 知识 HTML 清理、文件类型/大小限制、文档转换隔离、原图/证据授权、固定统计 SQL 及分页边界已有对应测试。
- 业务 AI 默认不外传资料；启用需显式配置且网关限定字面回环地址。不能仅因网关在本机就推断下游模型离线。
- 修改密码的原密码验证现在也有独立账号限流。生产仍须 HTTPS、正确的代理配置、最小权限数据库账号以及备份/恢复措施。

这属于源码与本地回归检查，不构成“绝对安全”或生产渗透测试结论。
