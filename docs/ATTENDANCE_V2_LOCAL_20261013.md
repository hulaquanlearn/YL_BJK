# 考勤核查第二版：本地验证

状态：本地源码验证版，尚未纳入部署包或生产部署。应用版本仍为 V1.9.10，考勤分析规则版本为 2，规则修订号为 4。

## 判断与展示

- 正常打卡时限默认2小时，可选30分钟、1小时、2小时、4小时。正常下班窗口从应下班时间至所选时限，包含截止边界；遇下一班开始则截断，下一班开始时的记录不重复归属。更改时限自动重算当前结果，保留备注、筛选及所选记录。
- 按同一人员跨日时间线处理。班内出门后返回保留为外出明细；正常窗口内有平衡往返时使用可关联的最后一次出门。
- 正常窗口之后、或临近下一班已进门后的出门仅为后续上下文，不消除上一班的记录缺口。不会把出门前已经重新进门的下一次活动补作上一班下班离场。
- 同一通道、同设备、同方向的连续刷脸，在首次刷脸起3分钟内按一次进出核查，使用最后一次刷脸时间，原始行及每次时间全部保留。可能是闸门未开后的重试，不据此认定真实开闸成功。中间出现反方向记录不合并，不跨排班开始、结束、正常窗口及相邻班次归属边界合并。
- 无法按重复刷脸解释的连续同方向、同秒进出冲突或下班窗口内返回后未见关联出门，标为进出顺序待核查。未见返回的下班前出门保留为线索，不直接作为违规结论。
- GPS、外出、顺序疑点、文件范围不足分别展示，可同时出现。GPS不能证明操作者或实际离场方式；人工通道与外出审批通过核查备注记录。
- 提前出门标签使用直白的“提前出门”，详情说明应下班前出门且未见返回。厂外培训由核查人员在备注中手动记录时间、返厂或直接下班情况及依据；当前备注不会自动更改分析分类，也不凭GPS推断培训。
- 界面只提供正常打卡时限设置；超出所选正常窗口的进出作为后续上下文，不补算本班正常离场。详情和CSV分别列出本班关联出门与后续记录，保留原表行号。
- 文件起止范围覆盖检查不保证每个人或设备记录完整；文件末尾不足时不据此认定缺出门。已经观察到的出门事实仍保留。
- 顶部两份文件、正常打卡时限和“开始分析”按钮同一行等高对齐。月份从排班文件名、前20行的明确年月标题或日期表头识别；来源冲突提示核对，只有月份而没有年份时弹窗补选，不猜当前年份。
- 页签按“全部排班、正常下班、提前出门、待核查”排列，默认全部排班；只保留班次和姓名/工号筛选，移除核查结果下拉及提前时长筛选。班次按原表首次出现顺序并跟随匹配人员，显示当前筛选班次数。
- 全部清单同时显示原表声明的休息、请假及空排班，不将它们计作缺勤或待核查工作班次；显示工作班次及非工作天数。全员默认按提前时长从长到短，搜索单个员工时默认日期从早到晚，日期和时长表头支持升降序；空时长始终排后。导出按清单顺序，非工作日期的闸机、观察窗与覆盖状态留空，不能向工作班次接口保存这些日期的备注。
- 个人考勤详情通过明确的按钮打开居中宽弹窗：桌面月历与每日记录并排展示，窄屏上下排列。用月历显示每天上班、休息、请假及空白，汇总工作与休息天数并列出提前出门日期；不把某类核查结果数量当成全部排班。休息日不生成工作班次。
- 导入提醒默认折叠，摘要显示提醒数量、“展开/收起”和箭头；展开后查看导入统计、提醒及核查口径。

## 历史报告

旧分析结果提示重新分析。重新导入同月同源文件时，规则版本变化会更新分析结果，复用原文件并保留备注；显式重新分析保留班次键和备注，继续使用版本检查避免覆盖。

本地资料管理的“本地测试”示例已补齐模拟源记录：检查通报与截图可按保留期清理并生成审计，已引用任务附件禁止清理；操作仅作用于测试fixture内存。

资料管理按功能后资料类型组织，提供当前功能、类型和日期范围的一键清理。预览包含所有分页的可清理数量与容量；确认提交后重新检查版本、保留期、引用及处理中状态，任一变化整批回滚并要求刷新核对。超过1000项时要求缩小范围，不静默截断。批量清理同一工作记录的多张截图时保留工作文字及其更新时间，逐项写入审计。本地重启前保存并恢复已导入原文件、报告、备注及清理状态。

验证重点：所选时限及边界、自动重算与备注保留、班内多次往返、最终未返回出门、跨午夜、下班GPS但无闸机出门、下一班归属、同通道重试、进出冲突、数据不足、月份识别、个人月历及本地示例清理。生产MySQL、生产登录及现场人工通道情况未实测。
