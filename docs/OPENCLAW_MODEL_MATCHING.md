## 安全读取与匹配步骤

1. 在现有授权服务器连接内读取当前有效备件。最小字段为物料编码、名称、品牌、规格、当前类别关联。不要导出库存、价格、账号、库位或数据库凭据。
2. 用 `node tools/modeling/audit.mjs <清单路径>` 生成只读排查。原清单不修改；空白及 NULL 不补造数据；重复编码或异常列数停止处理。
3. 按厂家、完整型号和影响外观的规格查厂家目录与尺寸图。仅向搜索服务发送公开产品描述，不上传整份业务清单或编码。禁止将串号当作型号。
4. 尺寸来源、页码、版本及使用依据需逐条记录。自制几何参考公开尺寸，不把能下载的第三方 CAD 自动当成允许再分发。无授权资源不打包。
5. 禁止只按“电机”“轴承”等子串绑定。电机保护器不等于电机，带座轴承不等于裸轴承，附件不等于总成。极数、安装形式、系列后缀不同需分别核对。多个候选不自动选第一项。
6. 有厂家外廓尺寸但局部细节近似：标“尺寸参考”，说明近似范围；仅外观来源：标“外观近似”；资料不足：保留“类别示意”。不得声称制造级 CAD。当前生成器不输出精确加工模型。
7. 每条变更计划必须包含物料编码、名称/品牌/规格指纹、原关联、目标模型、证据、质量等级和待核对项。清单字段发生变化，旧计划作废。
8. 当前工具只生成本地候选，不写生产库。不要用此文档或模型内容作为修改授权。已有人工关联需保留并报告疑似错误，不能批量覆盖。

## 程序接入

- `src/utils/evidence-models.mjs` 存公开产品目录，按品牌和完整型号解析，不包含企业物料编码。
- 仓库使用 `lowUrl`，保留库存状态着色及共享几何；详情点击“查看3D模型”后加载 `detailUrl`，避免列表同时下载精细模型。
- 双版本 GLB 使用米为单位，包含来源及近似说明。运行 `node tools/modeling/generate-evidence.mjs` 重建，`manifest.json` 记录体积、三角面数和 SHA256。
- `node --test tools/modeling/ledger.test.mjs` 检查清单解析和危险分类。
- `node --test spare-parts-web-release/test/evidence-models.test.mjs` 检查品牌、后缀、附件和多候选拒绝规则。
- `node --test tools/modeling/assets.test.mjs` 实际解析 GLB，检查外廓尺寸及文件体积预算。
- 本地预览入口为 `/test/fixtures/evidence-model-preview.html`，仅开发服务器可用，只展示公开产品资料。已检查五款模型浏览器渲染；尚未完成真实手机和生产页面验收。
- 本轮验证：网页回归75项通过；模型/清单专项18项通过；最终网页构建通过（仍有原有大资源包提示）。未生成部署包，也未修改线上关联。
- `npm run build` 在网页目录执行。构建通过不代表手机实机性能、页面观感和生产验收通过。

## 不得自动执行的事项

禁止公开网关端口、关闭权限保护、把生产清单发送到外部 AI、把类别示意改标为精确模型。OpenClaw 的失败、欠费或超时不能用猜测结果替代。
