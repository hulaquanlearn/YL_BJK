## 本轮保留的控件

1. 库位的旋转、俯视、复位、二维/三维、列表和全屏服务不同操作，不属于重复筛选。
2. 统计页库存范围和操作统计周期影响不同数据，保留；不同单位的库存数量不能直接相加，说明保留。
3. 小程序清空关键词与重置全部筛选作用不同；盘点正常/异常、批量标记正常有实际业务用途。
4. 库存概况刷新同时更新概况和列表；模型库刷新覆盖模型及关联数据，不简单等同于单个搜索，因此保留。
5. 上传材料、识别、人工核对、保存与导出属于不同步骤。检查通报的保存状态和人工确认不可为了简洁删除。
6. 全角色功能入口继续可见，数据访问及修改仍按已有车间、岗位和服务端权限执行；本轮不扩大授权。

- 小程序检查首页、列表、筛选、详情、统计、盘点和账号相关模板/流程源码。本机未通过微信开发者工具或真机完成视觉验收，因此不宣称小程序整体体验通过。
- 网页现有测试 83/83 通过，生产构建通过。本轮未改服务端，不以重新跑服务端测试替代实际体验检查。

## 经验与下一步验收

1. 先理解功能，再调整界面。相似外观不代表作用相同；删除前核对事件和数据范围。
2. 手机上先让用户看到要找的记录，再展示汇总。统计卡片不能抢占整个首屏。
3. 筛选应靠近受影响的内容，选中状态必须明确；少用页面外部的全局时间选择。
4. 统一字体、间距和按钮规则，保留模块配色差异；不能仅靠追加覆盖样式而忽略旧颜色遗留。
5. 空状态只解释当前缺少什么，以及在哪里开始，避免重复的大插图和重复按钮。
6. 功能可发现与操作授权分开。入口可见不代表可以读取其他车间数据或执行写操作。
7. 真实照片、长名称、大数据、待审批与已发布状态仍需使用真实测试账号回归；小程序需开发者工具及 Android/iOS 真机验证滚动、选择器和图片交互。

本轮结论是发现并修正了一批明确的冗余、密度和反馈问题，不代表所有状态、所有设备已经不存在问题。
