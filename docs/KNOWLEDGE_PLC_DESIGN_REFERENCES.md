# 工程知识与程序分析设计依据（V1.4.0）

本文记录本次工程知识库、OpenClaw 检索问答和工业程序静态分析的设计取舍。实现为本项目独立代码，没有复制下列项目源码。

## 可核实的参考项目与许可证取舍

| 项目 | 本次采用的产品原则 | 许可证及处理方式 |
| --- | --- | --- |
| [Outline](https://github.com/outline/outline) / [API](https://www.getoutline.com/developers) / [Security](https://docs.getoutline.com/s/guide/doc/security-DlJBglbImQ) | 文档修订历史、成员权限、审计与可追溯来源 | BSL 1.1；仅参考公开的产品行为和安全边界，不复制实现代码 |
| [Docmost](https://github.com/Docmost/docmost) | 查看与编辑分权、操作前先验证资源权限、文档版本可恢复 | AGPL-3.0；仅参考交互原则，不引入其代码或组件 |
| [Beremiz](https://github.com/beremiz/beremiz) / [架构说明](https://beremiz.readthedocs.io/en/latest/overview.html) | IEC 61131-3/ST 应按编译器式管线分析，必须明确静态解析与 PLC 现场执行的边界 | GPLv2+（部分运行时为 LGPL）；没有链接或复制其代码，当前系统只做自主实现的只读静态索引 |
| [RuSTy](https://github.com/PLC-lang/rusty) | 诊断结果应带源码位置、符号定义、读写引用与调用关系 | LGPL-3.0/GPL-3.0；只采用诊断展示思路，不复制编译器源码 |

选择这些轻量增强而没有嵌入完整 Wiki 或 PLC IDE，是为了保留当前 Express/MySQL/Vue 架构、降低部署和授权复杂度，也避免把生产资料发送到公开服务。

## 工程知识契约

1. `fermentation_knowledge_entries.id` 是知识条目的稳定标识；标题、附件显示名和正文修改时不能改变该标识。
2. 当前版本号由 `revision_no` 保存。每次编辑、替换附件或恢复旧版前，完整快照写入 `knowledge_entry_revisions`，包括正文、附件存储引用、索引状态和操作人。
3. 作者和系统管理员可以编辑、替换附件、恢复历史与删除；其他账号只读。编辑接口在接收附件之前校验作者/管理员权限，并在数据库事务中再次锁行复核。
4. 原文件名仅是显示字段，可修正乱码或误写，但不能借此改变真实文件扩展名。服务器存储名始终为随机名。
5. `index_status` 取值为 `pending`、`ready`、`empty`、`failed`；失败原因写入 `index_message`。重建失败时保留此前可用的 `content_text`，避免一次工具故障破坏现有搜索。
6. 旧附件升级后先标记待索引；作者或管理员可在详情页重试。页面显示状态与明确失败原因，不把“可下载”误报为“已完整识别”。
7. 所有允许上传的格式都有受鉴权的在线入口：浏览器原生支持的 PDF、图片、音视频直接查看；Office 优先转换为 PDF；文本/源码安全转义后查看；专有 CAD、压缩包或无法还原的格式显示文件信息并保留下载。信息预览不等于格式内容已完整渲染。

## OpenClaw 检索问答契约

1. 检索以最近三轮用户问题组成上下文，最新一轮优先；编码、中文设备/工段片段均可成为检索词。
2. 知识证据必须包含命中的正文片段，而不只是标题；备件证据必须保留数量和单位、车间、货区、库位与不含税单价；设备证据包含设备型号和所绑备件。
3. 每条证据返回稳定来源链接：`/knowledge?entryId=...`、`/inventory?inventoryId=...` 或 `/equipment?equipmentId=...`。页面点击证据能回到原记录。
4. OpenClaw 只能根据服务器传入的证据回答。资料不足时必须明确提示，不得编造库存、单位、价格、库位、设备参数或故障结论；不同单位的库存不能直接相加。
5. 文档正文视为不可信数据，不能覆盖系统规则或要求执行命令。公开网页检索、外部模型调用和诊断日志均不得携带原始私有程序、附件或业务明细。

## 工业程序分析契约

1. 当前功能是只读静态分析，不连接 PLC/机器人、不下载、不写入、不启停、不强制信号，也不声称执行了程序。
2. TIA `.ap16/.ap17` 原生项目必须在安装对应 TIA Portal 的 Windows 解析节点处理；服务器不能解密受保护块。ABB RAPID 与可读 ST/SCL/导出包可以直接建立静态索引。
3. 程序对象通过 `stableKey = SHA-256(sourcePath, itemType, blockType, sourceRef, name)` 的前 32 位建立来源稳定标识；数据库行 ID 只负责当前导入实例。
4. 交叉引用返回定义、调用、读取、写入和地址的真实源码行号。调用图只连接名称能够匹配到已导入程序块的边；库指令、动态调用、未导入模块和启发式误判都留在“未解析调用”中。
5. 覆盖率只描述已导入、可读、已建立引用索引的对象比例，不代表测试覆盖率、现场执行路径或功能正确性。受保护内容、重复定义和未解析调用以风险提示单独展示。
6. `.plcai` 回传以 SHA-256 幂等；同一结果重复提交不会重复写入。解析结果替换使用事务和项目行锁，且任务选择不会反复派发已经保存 `.plcai` 的部分解析项目。

## 设备、模型与知识的后续稳定标识建议

当前设备关系中仍存在名称字段。后续数据库升级应新增不可变的 `equipment_model_uid`（UUID）以及知识条目的可空 `equipment_model_id` 外键，同时保留名称快照供显示和历史追溯。导入、改名和合并均以稳定 ID 关联，不能依赖可变名称。

类别模型也应以模型记录 ID 为唯一关系来源。类别模型记录同时保存 3D 文件和代表图片；给备件绑定类别模型时，页面应通过该 ID 同时取得模型与图片。页面上的`匹配关键词`只用于管理员查找、筛选类别模型，不是必填项，也不参与离线关联脚本的确证规则；管理员确认后的模型 ID 才是权威关系。

## 升级与运维检查

执行迁移前必须先确认当前发布版本和数据库目标，并完成数据库及知识附件目录备份。不要在未显式选择目标库时运行迁移，也不要用全量 `schema.sql` 覆盖生产库。具体顺序、站点 `dist/` 目录、迁移命令和回滚步骤以发布包根目录的 `DEPLOY_V1.4.0.md`（源码工作区为 `output/DEPLOY_V1.4.0.md`）为准；附件应备份生产环境 `KNOWLEDGE_UPLOAD_DIR` 实际指向的目录，不能假定固定安装路径。

文档转换服务推荐安装 LibreOffice、Poppler (`pdftotext`/`pdftoppm`) 与 Tesseract（含 `chi_sim`、`eng`）。部署后由系统管理员访问 `GET /api/knowledge/preview-capabilities` 检查能力；缺少依赖时仍提供安全降级预览，但 Office 布局、PDF 文本或图片 OCR 会明确显示不可用。
