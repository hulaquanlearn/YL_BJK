# 制曲组长填报与每周评分 V1.9.7

日期：2026-09-28。当前为本地源码调整，已打包、未部署，也没有创建 Codex 聊天提醒。评分调度在业务 API 内执行。

## 使用方式

- 组长登录后默认进入“我要填报”，当日填报、本周任务、随时记录分开；未提交事项优先，照片要求明确显示。填报完成后更新数量，已提交事项折叠。持续事项没有发生时不强制填报。
- 组长始终绑定当前登录人，不显示人员选择框、人员总览或管理员配置；请求不传人员选择参数，由服务端使用会话身份。伪造其他 userId 会返回 403，本人未配置时显示联系管理员提示，不回退选择其他人。
- 班长默认进入“履职统计”，通过上一周、回到本周、下一周及周选择器切换周一至周日；点击人员与日期交叉格查看具体事项、结果及材料。“本周考评”可看到每个人的建议总分、正式成绩和评分理由摘要。点击“查看评分与依据”可逐项查看标准、建议、记录、照片和班长确认分；原始全量台账放入折叠区域。
- 每周日北京时间早上 08:00，服务排队为当前启用的制曲组长生成当周建议评分。自动任务只在 08:00 这一分钟接收任务，按人员顺序处理，全部完成可能晚于 08:00。每人的实际生成时间保存在结果中；材料以读取时已提交内容为准，不把周日全天视为已经结束。
- 平时打开页面或填报、修改材料不调用模型。材料/评分标准变化后，旧建议标为待核对，不自动重评；已发布成绩保留历史。
- 仅系统管理员能用“立即生成 AI 评分”按钮对所选人员、所选周次评分。班长及车间管理员仍可人工复核，不可调用手动 AI 接口。
- 建议分不能代替最终成绩。班长核对照片、调整分数和理由后发布；人工发布保留采用的建议编号及改分记录。

## 部署要求

1. 备份现有数据库及原部署文件，将 `work_score_jobs` 纳入备份范围。
2. 本次增量文件是 `server/sql/migration_work_score_jobs_20260928.sql`，仅使用 `CREATE TABLE IF NOT EXISTS`。API 启动时也会幂等补建，不需要重放历史迁移或导入业务台账。
3. 前后端必须一起更新并构建。API 完成数据库/表结构检查后才启动定时器；单独运行网页不能触发评分。
4. 保留现有 OpenClaw 本机网关与数据传输限制。需要已有的 `AI_CONTEXT_TRANSFER_ENABLED`、本机 OpenClaw 地址、凭据和文本模型配置正确；此次没有替用户开启外传配置。图片不发给模型，照片必须人工核对。
5. 定时器按 UTC+8 运算，不依赖服务器本地时区。API 必须在周日 08:00 运行。停机错过这一分钟不会在周中补跑，系统管理员可手动补评。

## 重复、失败和中断

- MySQL 命名锁阻止同一人员同一周的同时评分。自动任务以“周次＋人员”唯一键防止多进程、重复轮询或重启后重复评分；管理员手动重评另留任务历史。
- 未配置模型、模型错误、无评分标准或超长材料会记录失败，不返回零分假装成功，不自动重复调用。超过当前 26000 字符请求材料限制时明确失败，不能截断后冒充完整评分。
- 评分期间材料或标准变化、成绩被发布，结果拒绝保存。已发布成绩不能直接重评覆盖。
- 进程异常退出可能保留“处理中”；管理员再次触发后，取得该人员评分锁即可将中断任务标为失败并重试，不用删除历史。
- 本次未增加通知渠道。任务结果在人员总览、评分详情和数据库任务记录中查看。

## 验证与边界

本轮包含北京时间/跨年周次、周中不运行、持久任务去重、并发锁、失败记录、管理员独占触发权限、建议跨账号读取、过期建议提示、班长复核系统生成建议的自动测试。

浏览器使用本地合成接口和演示账号检查页面及操作；不连接正式数据。真实 MySQL 锁竞争、迁移、真实 OpenClaw 评分、生产进程保活以及真实手机上传仍须现场验收。既有 UI 验证脚本中旧页签及文案的断言不能作为新版验收结果。

最终本地结果：后端 204/204、网页 81/81 测试通过，Vite 生产构建通过（仍有既有大分包提示）。内置浏览器合成数据检查了 390px 组长首页与填报提交、班长评分摘要和逐项建议、1280px 管理员评分详情；组长无人员选择/人员总览/配置/手动评分/发布入口，填写提交后待填数量从 11 更新为 10。预览未使用真实数据库或模型。

本轮补充：自然周跨年转换、每日/每周/持续事项统计、重复记录、未来日期及班长统计接口权限测试。统计按当前启用成员和现行职责目录展示；未填报不等同未完成，不直接认定缺勤或扣分，持续事项无记录不计漏填。浏览器合成数据验证了 1280px 与 390px 布局、上一周/回到本周、人员日期格筛选与只读材料查看。
