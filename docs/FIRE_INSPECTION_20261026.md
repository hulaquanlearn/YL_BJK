# 消防点检与一物一码

## 入口与首次设置

网页进入“工作管理中心 → 消防点检”；安卓 App 进入“工作 → 消防点检”。网页和 App 共用账号、区域授权、器材及点检记录。小程序不增加消防入口，原功能保持。

系统管理员依次完成：

1. 打开待确认的 Excel 导入，核对位置、重复编号和数量空缺，选择要进入台账的源行后确认。疑似重复默认不选，不会自动合并；原文件和来源行继续保存。
2. 在“设置 → 人员授权”选择人员及消防负责区域。此授权不开放履职、备件修改或审批。
3. 在“更多操作 → 新建点检周期”填写名称、区域和可选截止时间。按创建时点位、器材形成本轮任务范围，新加入器材需纳入后续周期。
4. 根据区域或器材筛选，批量生成标签并打印；也可以在器材明细中下载单个二维码。

提供的台账共1003条来源记录，包含灭火器744条、消火栓259条。两条灭火器备注“暂未配置”，另六条消火栓数量空缺；数量待核共8条。出厂日期和生产厂家进入器材档案，不产生虚构的历史点检记录。导入预览保留7天，过期需重新校验后确认。

## 一物一码与现场工单

每件已确认的实物器材有稳定二维码。同一位置放多具灭火器时，各件二维码不同；换盘点周期不需要重新贴码。相同业务编号不作为系统合并键。新增数量大于1的正整数记录逐件建立档案，保留原始数量和第几具的来源信息；未知数量、未配置及退役条目不打印实物标签。

扫码登录后直接打开该件器材最近一个获授权、尚开放周期的点检工单。已检查显示本期记录；没有本期任务显示未派发，不自动创建或提交工单。App扫码需要android.7或后续兼容版本；手机网页可通过器材链接或编号查找打开。

现场逐项填写实际结果，拍摄或选择照片，点击“提交点检”。上传失败或提交失败时保留当前填写；请求重试不会重复生成记录。单件工单只能关联为这件器材上传的本人照片。位置入口可以检查该点位剩余未检器材，已检器材不会被重新覆盖。

红色表示本轮未点检，绿色表示本轮已有有效记录。同一位置有多件器材时显示“已检几件/总件数”，全部完成后该点位才变绿。异常、缺失、未配置、数量待核与“是否已检”分别记录，未闭环异常跨周期保留提示。

## 记录、照片与整改

点检人从登录账号获取，服务端记录提交时间。正常现场点检无需手填日期；补录单独填写实际检查时间和原因，记录中同时保留提交时间。按北京时间展示到秒。

每次提交保留器材、位置和人员快照及对应照片，后续更换器材或新建周期不覆盖历史。已完成记录不可修改；后续检查使用新周期。只允许撤回本人尚未提交的照片，服务器以标记方式保留回收资料，不能删除历史点检凭证。

异常形成待整改事项。处理人填写情况并上传整改照片后进入待复核；系统管理员复核关闭或重新打开。整改提交人不能复核自己的处理。关闭异常不改写原始检查结论、照片和操作历史。

“更多操作 → 导出点检记录”导出选定周期/区域的人员、实际时间、提交时间、结果、器材明细及照片数量；照片仍通过授权页面查看。

## App、权限与后续展示

安卓包沿用`cn.digitalworkbench.mobile`及正式签名，使用App中的更新入口或同站正式链接覆盖安装；网页/API更新不能替代安装新的相机扫码版本。相机使用私有FileProvider临时图片，扫码在本机解码；拒绝外站、无效器材参数和旧账号回调，不自动提交记录。

消防区域和点位保留楼栋、楼层、房间及空间扩展字段。后续平面图和建筑3D应使用相同器材身份和点检记录；本期未制作建筑模型。

全站仍为V1.9.10。消防仅执行`server/sql/migration_fire_inspection_20261026.sql`的独立`fire_*`增量建表；不重跑历史初始化SQL，不改库存、履职或已有上传。正式来源Excel保存在私有导入记录中，不进入网页成品、源码仓库或公开发布包。

本轮服务器备份和核验资料位于`/opt/spare-parts/rollback/fire-inspection-20261026/`。恢复时先保存新增消防记录和照片，恢复`server-before/`中的旧代码及`web-dist-before/`完整网页，重启经核对的`spare-parts-api`与`spare-parts-web`。新增数据库结构及已产生业务数据保留，不能以旧空库覆盖或删除消防表。安卓只回退更新清单不会自动降低用户已安装的versionCode。

真实MySQL流程验证使用独立`fire_qa_20261026*`测试表及合成账号，不向正式消防台账写入模拟点检。模拟器、合成浏览器和隔离数据库检查不代表厂商真机及现场人员的实际业务验收；实际验证结果记录在当前QA文档。
