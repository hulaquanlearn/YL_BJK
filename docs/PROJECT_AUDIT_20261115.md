## A01 / P1：旧密码登录可跨越改密边界，改密后仍生成有效会话

### 定位

- [登录路由：29–44](<../server/src/routes/auth.js#L29-L44>)：读出用户、验证密码之后，再执行异步更新、创建会话；没有在创建会话时核验用户密码版本是否仍一致。
- [改密路由：66–86](<../server/src/routes/auth.js#L66-L86>)：更新密码及 `token_version`，删除该用户当时已有会话。
- [会话创建与鉴权：35–65](<../server/src/auth.js#L35-L65>)：会话只保存用户、令牌哈希和到期时间；请求鉴权不使用用户密码版本。单纯增加 `token_version` 不会使之后插入的会话失效。

### 已复现的顺序

1. 登录请求 L 使用原密码，已完成密码校验；在 `last_login_at` 更新处暂缓。
2. 同一账号的改密请求 C 完成：密码改成新值，版本增加，删除所有已有会话并提交。
3. 放行 L；它继续调用 `createSession`，向会话表插入一条新会话并返回令牌。
4. 将此令牌交给实际 `requireAuth`，鉴权仍成功。

这不需要破解令牌；在原密码泄露后的改密场景里，一个已通过原密码校验的并发登录请求可能跨过撤销边界。未连接生产系统验证实际利用，不声称已经发生账号入侵。

### 建议修复

将“最终确认凭据仍有效/账号仍启用 + 会话创建”与改密/管理员重置密码使用相同的账户级串行化边界，例如事务内锁定用户行后重新核验；或先做耗时密码校验，再在事务中比较最初读取的哈希/版本，保证比较与插入会话原子化。若采用会话版本方案，须真正存储并在鉴权时校验会话版本，不要只增加用户表字段。

同时复核改密自身的检查—更新时序：目前旧密码验证位于事务外，不能让已校验旧状态的请求覆盖随后发生的密码重置。此项是相关代码风险，本轮独立探针直接覆盖的是“登录跨改密”场景。

### 验收

- [ ] 用确定性同步点覆盖“登录先校验 → 改密提交 → 登录继续”；原凭据不能获得改密后的可用会话。
- [ ] 同步覆盖管理员重置、账号停用与登录交错，不能只测正常顺序。
- [ ] 两个并发改密请求不能都基于过期密码状态提交；行为需可解释且不覆盖最新凭据。
- [ ] 正常登录/改密、资产 Cookie、到期/退出登录仍有效；不改变现有角色/车间语义。

## A02 / P2：辅助网页客户端与小程序缺少请求会话隔离

### 定位

- [office 客户端：5–12](<../spare-parts-web-release/src/api/office.js#L5-L12>)。
- [rawDuty 客户端：6–12](<../spare-parts-web-release/src/api/raw-duties.js#L6-L12>)。
- [小程序请求封装：26–56](<../miniprogram/services/api.js#L26-L56>)，以及 [goLogin：45–49](<../miniprogram/services/auth.js#L45-L49>)。
- 可参考已有正确防护：[主网页 API 客户端：13–55](<../spare-parts-web-release/src/api/index.js#L13-L55>)，它会记录发送时的会话，检查成功/失败响应以及 Blob 解码后的会话是否仍一致。

### 已复现

三个遗漏的客户端均存在：

1. 账号 A 发起请求。
2. 退出/重新登录或共享存储的其他标签页将当前会话变为账号 B。
3. A 的请求稍后返回 401。
4. 错误拦截器不比较请求所属令牌，直接清除 B 的会话并跳登录。

对于成功响应，A 的数据在 B 登录后仍会正常 resolve，而非按过期请求取消。**这证实网络封装缺少隔离；是否实际展示旧数据还取决于具体页面生命周期，本轮未在浏览器证实跨账号数据展示，不应夸大为后端越权。**

两个网页客户端的超时分别为 180 秒和 120 秒，长请求/跨标签切换较容易落入该时序。网页与原生壳共用相关网页逻辑；小程序需单独改请求封装，不能只修主网页 API 客户端。

### 建议修复与验收

- [ ] 每次发送记录会话标识，成功和失败回调最先比较当前会话；不匹配时以“过期请求/取消”结束。
- [ ] 旧 401 不清当前登录、不跳转、不弹当前账号的错误提示；旧成功响应不向业务页面交付。
- [ ] 错误 Blob 异步解析后再次检查会话，避免在 `await` 窗口切换账号后仍清会话。
- [ ] 当前会话真正失效时仍能清理并回登录；不要把所有 401 一律吞掉。
- [ ] 覆盖同标签重新登录、跨标签存储切换、小程序重新登录和退出后的迟到响应。
- [ ] 如果抽取公共实现，保留履职业务的独立写权限策略，不能为了复用拦截器把普通员工合法履职写入误拦截。

## A03 / P2：设备型号改名后，原名被旧内部编码永久占用

### 定位与根因

- [编码生成：27–29](<../server/src/routes/operations.js#L27-L29>)：`equipment_code` 是“车间 + 初始名称”的确定性哈希。
- [新建：330–342](<../server/src/routes/operations.js#L330-L342>)：先按当前名称检查重复，再生成同一个哈希编码，编码冲突也被解释为型号重名。
- [改名：365–382](<../server/src/routes/operations.js#L365-L382>)：只更新名称等字段，正确保留原内部身份/关系，但也保留了原名派生的编码。
- [数据库唯一约束：7–19](<../server/sql/migration_operations_20260718.sql#L7-L19>)：`equipment_code` 全局唯一。
- [已有改名测试：29–39](<../server/test/equipment-maintenance.test.js#L29-L39>) 明确要求保留内部身份，但未覆盖改名后复用原名称。

### 复现

在同一车间：新建 `Audit-A` → 改名为 `Audit-B` → 再新建 `Audit-A`。

最后一步按名称查不到重复记录，但生成的编码仍是旧记录占用的编码，实际路由返回 409“设备型号已存在”。类似生成逻辑也用于 [导入新增设备：268–277](<../server/src/routes/operations.js#L268-L277>)，应联动检查，不只改手动新建。

### 建议修复与验收

内部身份与可修改展示名称解耦。优先保留现有记录编码及关联，新建时采用独立唯一编码/可靠冲突策略；不要以删除旧型号、清关系或批量重建台账来解决。名称唯一性如需用数据库约束保障，应规划幂等迁移并检查已有数据，不能直接批量改现场表。

- [ ] 新建 A → 改名 B → 新建 A 成功，两个型号各有独立身份。
- [ ] 第一个型号既有备件关联不丢失；改名/停用/恢复不变更其身份。
- [ ] 原名再次导入也按预期创建，不误关联至已改名型号、不报内部唯一键错误。
- [ ] 当前仍存在的同名型号继续被正确拒绝；跨车间与并发创建也有回归覆盖。

## A04 / P2：批量出入库数量必填校验缺失，接受非数字类型

### 定位

- [可空数字解析：125–129](<../server/src/routes/operations.js#L125-L129>)：空串/null/undefined 返回 null，其余直接 `Number(value)`。
- [批量路由：455–494](<../server/src/routes/operations.js#L455-L494>)：将其用于必填的 `items[].quantity`，随后进行加减、更新库存、写流水。
- [流水表：178–184](<../server/sql/migration_existing.sql#L178-L184>)：数量字段 `NOT NULL`。

### 已复现的输入/行为

基础请求：

```json
{"type":"in","reasonCode":"other_in","items":[{"inventoryId":1,"quantity":true}]}
```

| 数量输入 | 当前解析/后果 |
| --- | --- |
| 不传、null、空串 | 解析为 null，未在进入事务前拒绝；到达库存 UPDATE 和流水 INSERT。依据表约束，真实 MySQL 的严格非空校验会使流水插入报错并回滚，形成数据库错误而非明确 400。此后半段由 SQL 约束推导，本轮未连接 MySQL 实测。 |
| true | 解析为 1，以 1 执行库存修改/流水写入，不会按非法类型拒绝。 |
| [2] | 解析为 2，以 2 执行库存修改/流水写入，不会按非法类型拒绝。 |

空数量路径有事务回滚保护，**不据此宣称库存已部分提交**；更明确的业务问题是布尔值/数组会被当成合法数量处理。

### 建议修复与验收

- [ ] 必填数量单独使用严格解析器；仅接受有限数字或非空的合法数字字符串，拒绝 null、缺失、布尔、数组、对象、空白串。
- [ ] 在获取连接/开启事务前返回可理解的 400；也验证每个 item 是正确对象，避免 null item 变成 TypeError/500。
- [ ] 数量范围、小数精度按现有业务规则统一，不放松出库非负库存约束。
- [ ] 验证正常整数/小数入出库、重复 ID、盘点锁定、跨车间和事务回滚行为不回退。
